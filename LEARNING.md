# Learning map

Nextto doubles as a learning project for **Next.js, TypeScript, Postgres
and Supabase**. This file maps each feature to the concepts it demonstrates
and where to find them. It grows with each increment.

Legend: ✅ shipped · 🚧 planned in a later increment

## Postgres (complex SQL)

| Concept                                                         | Where                                                                                                                                                                                 | Why it's here                                                                                                                                                                 |
| --------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ✅ `tstzrange` + **exclusion constraint** (`btree_gist`)        | `bookings_no_overlap` in [`core_schema`](supabase/migrations/20261019100100_core_schema.sql)                                                                                          | The database itself makes double booking impossible, even under concurrent requests. Violations raise SQLSTATE `23P01`.                                                       |
| ✅ Half-open ranges `[)`                                        | `bookings_during_valid` check                                                                                                                                                         | 10:00–11:00 and 11:00–12:00 touch but don't overlap.                                                                                                                          |
| ✅ **Partial** exclusion constraint                             | `... where (status in ('pending','confirmed','completed'))`                                                                                                                           | Cancelling a booking frees its slot automatically.                                                                                                                            |
| ✅ `generate_series` + **multiranges** (`range_agg`, `-`, `<@`) | `available_slots()` in [`booking_functions`](supabase/migrations/20261019100400_booking_functions.sql)                                                                                | Free time = shifts − (bookings + buffers, breaks, time off). Slots are a series over the free multirange.                                                                     |
| ✅ **Recursive CTE**                                            | `create_recurring_bookings()`                                                                                                                                                         | Generates N occurrences in local wall-clock time; one clash rolls back the whole series.                                                                                      |
| ✅ Time zones (`timestamptz`, `at time zone`)                   | `available_slots`, reports                                                                                                                                                            | Store instants; convert to `Africa/Nairobi` only at the edges. `date + time` gives a local timestamp, and `at time zone tz` turns it into an instant.                         |
| ✅ **Money as `bigint` cents**                                  | every `*_cents` column                                                                                                                                                                | No floats (a test asserts this). VAT uses basis points: `round(subtotal::numeric * bp / 10000)`.                                                                              |
| ✅ **Generated columns**                                        | `invoices.total_cents`, `balance_cents`, `invoice_items.line_total_cents`                                                                                                             | Derived values can never drift from their inputs.                                                                                                                             |
| ✅ **Gapless numbering** with row locks                         | `issue_invoice()` + `private.invoice_counters` in [`invoicing`](supabase/migrations/20261019100500_invoicing.sql)                                                                     | An `UPDATE ... RETURNING` on a counter row serialises issuers. Rollbacks don't burn numbers, unlike a `SEQUENCE`.                                                             |
| ✅ Triggers (BEFORE vs AFTER)                                   | VAT, freeze-issued, subtotal sync, payment state                                                                                                                                      | BEFORE edits `NEW`; AFTER updates _other_ rows.                                                                                                                               |
| ✅ **Idempotency**: unique key + `ON CONFLICT DO NOTHING`       | `record_mpesa_callback()` in [`payments_mpesa`](supabase/migrations/20261019100600_payments_mpesa.sql)                                                                                | Safaricom retries callbacks; the second delivery is a no-op.                                                                                                                  |
| ✅ Row locks (`FOR UPDATE`) and race handling                   | `apply_mpesa_callback()`, early-callback trigger                                                                                                                                      | Handles a callback that arrives before the payment row is committed.                                                                                                          |
| ✅ `jsonb` parsing                                              | `record_mpesa_callback()`                                                                                                                                                             | `->`, `->>`, `#>` and `jsonb_array_elements` over the Daraja payload.                                                                                                         |
| ✅ **Window functions**                                         | `report_revenue_trend()` in [`reports`](supabase/migrations/20261019100700_reports.sql)                                                                                               | Running total, 7-day moving average (`rows between 6 preceding`), and `lag()` for day-over-day change. `rank()` in busiest hours, `row_number()` in repeat customers.         |
| ✅ **Materialised view** + `refresh concurrently`               | `private.business_daily_stats`                                                                                                                                                        | Pre-aggregated daily stats for fast dashboards; it needs a unique index.                                                                                                      |
| ✅ **pg_cron**                                                  | `nextto-refresh-daily-stats`, `nextto-expire-stale-mpesa`                                                                                                                             | Scheduled jobs inside the database.                                                                                                                                           |
| ✅ Partial / composite / expression / GiST indexes              | See [docs/sql-notes.md](docs/sql-notes.md)                                                                                                                                            | Each one comes with an `EXPLAIN` showing it in use.                                                                                                                           |
| ✅ `FULL JOIN`, `FILTER`, `LATERAL`, `WITH ORDINALITY`          | matview, `create_business()`                                                                                                                                                          | Combining sparse daily series; expanding preset JSON into rows.                                                                                                               |
| ✅ Views with `security_invoker = true`                         | `booking_details`, `customer_stats` in [`dashboard`](supabase/migrations/20261019100900_dashboard.sql)                                                                                | A plain view runs as its owner and would bypass RLS. An invoker view runs as the caller, so tenant isolation still applies.                                                   |
| ✅ `FILTER (WHERE ...)` aggregates                              | `customer_stats`                                                                                                                                                                      | Visits, no-shows, cancellations and spend in one pass over a customer's bookings.                                                                                             |
| ✅ State machine in a trigger                                   | `guard_booking_change()`                                                                                                                                                              | Only allowed status moves (e.g. cancelled is final), enforced for every client, not just the UI.                                                                              |
| ✅ `SELECT ... FOR UPDATE`                                      | `reschedule_booking()`                                                                                                                                                                | Locks the booking while it's moved; the exclusion constraint still rejects clashes (`23P01`).                                                                                 |
| ✅ `pg_trgm` GIN index                                          | `customers_name_trgm_idx`                                                                                                                                                             | Makes `ILIKE '%term%'` customer search indexable. See [sql-notes](docs/sql-notes.md).                                                                                         |
| ✅ SECURITY INVOKER vs DEFINER functions                        | `save_invoice_draft()` (invoker) vs `convert_quote_to_invoice()` (definer) in [`invoice_documents`](supabase/migrations/20261019101000_invoice_documents.sql)                         | Invoker functions run as the caller, so RLS still applies. Use definer only when the caller lacks a privilege (e.g. updating `invoices.status`), and check membership inside. |
| ✅ `ROWS FROM (jsonb_to_recordset(...)) WITH ORDINALITY`        | `save_invoice_draft()`                                                                                                                                                                | Turns the editor's JSON array into typed rows and keeps their order as `sort_order` in a single `INSERT ... SELECT`.                                                          |
| ✅ Lock the parent row against over-payment                     | `private.payments_validate()` (`SELECT ... FOR UPDATE` on the invoice)                                                                                                                | Two cashiers recording the last payment at the same moment are serialised, so the second sees the new balance and is rejected.                                                |
| ✅ Trigger `WHEN (...)` clause                                  | `invoice_adopt_booking_payments`                                                                                                                                                      | Fires only on the draft → issued change; a deposit paid at booking time moves onto the invoice.                                                                               |
| ✅ Invoker view with time-zone-aware status                     | `invoice_summaries`                                                                                                                                                                   | `is_overdue` compares `due_date` with _today in the business's zone_, not UTC. Backed by `invoices_outstanding_idx` ([sql-notes](docs/sql-notes.md)).                         |
| ✅ **Partial unique index** as a business rule                  | `payments_one_pending_mpesa_per_invoice` in [`mpesa_requests`](supabase/migrations/20261019101100_mpesa_requests.sql): at most one waiting prompt; `23505` maps to a friendly message |
| ✅ A **preflight function** that owns the rules                 | `prepare_mpesa_request()`: amount, phone, status and rate limit decided in SQL, so the guest and staff paths cannot drift apart                                                       |
| ✅ Custom SQLSTATEs (`22023`, `55000`, `P0002`)                 | `prepare_mpesa_request()` → [`mpesa/request.ts`](src/lib/mpesa/request.ts) maps each to UX                                                                                            |

## Supabase

| Concept                                                   | Where                                                                                                                                                                                        | Why it's here                                                                                                                                   |
| --------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| ✅ Versioned **migrations**                               | `supabase/migrations/`                                                                                                                                                                       | Every schema change is a reviewed, ordered file. CI rebuilds from scratch.                                                                      |
| ✅ **Row level security** per tenant and role             | [`rls`](supabase/migrations/20261019100200_rls.sql)                                                                                                                                          | Members read; owners configure; staff manage their own time off; anon sees nothing.                                                             |
| ✅ SECURITY DEFINER helpers in a private schema           | `private.member_business_ids()` etc.                                                                                                                                                         | Avoids recursive policies, and the private schema isn't exposed by the API.                                                                     |
| ✅ Column-level `GRANT`s                                  | businesses, invoices, payments                                                                                                                                                               | Clients can't set an invoice number, status or totals, even on rows RLS allows.                                                                 |
| ✅ Public access through functions only                   | `get_public_booking_page`, `available_slots`, `book_public`, `get_public_booking`, `get_shared_invoice`                                                                                      | The anon key can do exactly these things and nothing else.                                                                                      |
| ✅ Capability URLs (an unguessable uuid as the secret)    | `get_public_booking()` in [`public_booking_lookup`](supabase/migrations/20261019100800_public_booking_lookup.sql)                                                                            | A guest's confirmation link shows that one booking, with first name only and no contact details. pgTAP proves anon still can't read `bookings`. |
| ✅ A cookie-less `anon` client for public pages           | [`src/lib/supabase/anon.ts`](src/lib/supabase/anon.ts)                                                                                                                                       | It reads no cookies, so pages using it can be cached (ISR).                                                                                     |
| ✅ `auth.uid()` / `auth.jwt()` inside SQL                 | `create_business`, `accept_invitation`                                                                                                                                                       | Identity flows from the JWT into Postgres.                                                                                                      |
| ✅ Realtime publication                                   | `bookings` in `supabase_realtime`                                                                                                                                                            | Live calendar updates.                                                                                                                          |
| ✅ **Realtime** `postgres_changes` + RLS                  | [`live-updates.tsx`](src/app/dashboard/calendar/live-updates.tsx)                                                                                                                            | Events are filtered by `business_id` and checked against RLS. Gotcha: call `realtime.setAuth(token)` _before_ subscribing, or the join is anon. |
| ✅ **pgTAP tests** incl. RLS impersonation                | [`supabase/tests/`](supabase/tests)                                                                                                                                                          | `set local role authenticated` plus `request.jwt.claims` to act as any user.                                                                    |
| ✅ Seed data per preset                                   | [`supabase/seed.sql`](supabase/seed.sql)                                                                                                                                                     | Demo businesses for every business type.                                                                                                        |
| ✅ Auth magic links (token_hash flow) + staff invitations | [`/login`](src/app/login), [`/auth/confirm`](src/app/auth/confirm/route.ts), [`/invite/[token]`](src/app/invite/[token]/page.tsx), [email template](supabase/templates/magic_link.html)      | `verifyOtp({ token_hash })` works in any browser, so an invite sent by the owner can be opened by the invitee.                                  |
| ✅ SSR auth with cookies (`@supabase/ssr`)                | [`src/lib/supabase/`](src/lib/supabase), [`src/proxy.ts`](src/proxy.ts)                                                                                                                      | The proxy refreshes the session on every request; `getClaims()` verifies the JWT on the server.                                                 |
| ✅ Generated TypeScript types (`supabase gen types`)      | [`src/lib/database.types.ts`](src/lib/database.types.ts)                                                                                                                                     | `.from("services").select(...)` and `.rpc("create_business", ...)` are fully typed. CI fails if the file is stale.                              |
| ✅ **Service role vs RLS**: when bypassing is right       | [`supabase/admin.ts`](src/lib/supabase/admin.ts): only the callback route and the M-Pesa orchestrator use it, and only to call `service_role`-only functions                                 |
| ✅ Polling when Realtime would leak data                  | [`refresh-while-pending.tsx`](src/components/refresh-while-pending.tsx): guests (anon) can't subscribe to `payments` under RLS, so the page re-renders every 2.5 s while a prompt is pending |
| ✅ Calling SQL functions with `.rpc()`                    | [`onboarding/actions.ts`](src/app/onboarding/actions.ts)                                                                                                                                     | One atomic `create_business` call; Postgres error codes (`23505`) map to form errors.                                                           |
| ✅ On-demand PDFs instead of Storage                      | [`/dashboard/invoices/[id]/pdf`](src/app/dashboard/invoices/[id]/pdf/route.ts)                                                                                                               | Rendering from the database each time means a PDF can never be stale. Storage is kept for logos (increment 8).                                  |

## How to explore

```powershell
npm install
npm run db:start      # Postgres + Auth etc. in Docker, applies migrations + seed
npm run db:test       # 100+ pgTAP assertions
docker exec -it supabase_db_nextto psql -U postgres
```

Then try, for example:

```sql
select * from available_slots(
  (select id from businesses where slug = 'demo-salon'),
  (select s.id from services s join businesses b on b.id = s.business_id
   where b.slug = 'demo-salon' order by s.sort_order limit 1),
  current_date + 1);
```
